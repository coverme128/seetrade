# v1.0.4 运行时触发使用指南

适用版本：个人版 v0.5.1，保留合同 v1.0.4 运行时并扩展 v1.1 动态币种池。安装与账户准备见 [配置说明](EXECUTION.md)，启动、备份和故障处理见 [运维手册](OPERATIONS.md)。本文解释实际程序行为；原始合同保存在 `spec-v1.0.4`，不随使用指南修改。

## 从观察开始

1. 启动后打开市场工作台，检查 BTC / ETH 的 Binance、OKX 行情均已就绪，模式为 OBSERVE。
2. 进入“模型健康 → 执行与研究 → 运行触发诊断与配置”，查看当前标的状态、完整评估次数和触发配置版本。
3. 保留默认配置，等待历史预热。默认需要至少 32 个历史样本、采样间隔 250 ms；健康连续行情下约需 8 秒以上，恢复断连后会重新预热。
4. 出现正式预测后，观察原卡片的跟踪和自动结果；未执行的预测也有 Outcome。结果、交易和触发次数分别统计。

公共行情与 OBSERVE / PAPER 不需要交易所账号、密码或 Key。真实来源的初始模型没有通过校准，出现方向预测也不等于可以 PAPER 或实盘入场；查看卡片的资格拒绝原因。模型研究和手动晋升流程见 [README](../README.md#离线研究与-parquet)。

## 机会颜色与排序

首页和“预测与交易”顶部的多标的“当前机会”，按等级及合格净优势排序；绿色机会出现时显示“优先关注：BTC / ETH”，点击标的即可查看详情。高亮随最新有效资格更新，行情、评估或连接过期后撤下，不会因为旧数据保留在页面上就继续提示优先机会。

| 颜色 | 等级 | 判断依据 |
|---|---|---|
| 绿色 | 优先机会 | 校准有效、全部资格检查通过、净优势为正、Model Trust 为 HIGH |
| 蓝色 | 合格机会 | 校准有效、全部资格检查通过、净优势为正、Model Trust 为 DEGRADED |
| 黄色 | 待验证 | 校准或可信度未通过；原始概率再高也不提升等级 |
| 红色 | 未达标 | 已有校准和可信度，但成本或其他交易资格未通过 |
| 灰色 | 暂无 / 暂不可用 / 信息不足 / 已暂停 | 无当前预测、数据过期、资格快照不完整，或紧急停止 / 存储异常 |

这是展示分级，沿用核心的资格与可信度结果，没有新设交易阈值，也不改变模型、风险或 AUTO 资金准入。高等级仍可能被 AUTO 因预算、冷却、已有仓位等原因跳过；方向 LONG / SHORT 的原有颜色不代表机会质量，需看单独的等级标签。

首页最近五条预测和预测结果列表增加“开场机会等级”“开场净优势”。默认按等级优先，同级合格记录按开场净优势降序，再按预测时间降序；可切换为“预测时间最新”，切换页面保留本次排序选择。首页排序范围为最近五条当前标的记录，历史页为已加载记录，未查询的历史不参与排序。

历史等级只使用预测建立时保存的资格、校准概率和可信度，不使用最终命中、后来的最高资格或当前配置。资料不足的旧记录显示灰色，不补造等级。因此“优先机会”可以最终止损，“待验证”也可以目标先触达；历史颜色不表示当前还能入场。历史净优势只在已合格等级展示，其他记录显示“—”，详情仍保留原始研究数据。

当前机会页含动态文字提示与等级文字，颜色不是唯一辨识手段；本次没有增加系统通知、声音或后台推送。

## 四种运行状态

| 状态 | 何时出现 | 默认计算节奏 |
|---|---|---|
| `IDLE` | 没有活跃候选、Episode 或持仓 | 维护行情、标签路径和轻量 Pulse；没有固定每秒完整模型评估 |
| `CANDIDATE` | 轻量触发成立，等待正式预测条件满足 | 立即完整评估，之后约每 1.5 秒复核；默认候选 TTL 为 10 秒 |
| `ACTIVE` | 已有正式 Prediction Episode | 约每秒完整评估与资格复核 |
| `IN_POSITION` | 有 PAPER、确认成交或账户持仓 | 约每秒完整评估，并接受即时风险 / 数据保护 |

更强触发和保护可以提前唤醒评估，所以两个相邻评估不保证相隔整整一秒。界面轮询约每秒一次，也不是交易所事件到屏幕的延迟保证。

运行状态不替代预测生命周期。`CANDIDATE` 可以过期而没有预测；`IDLE` 时卡片可以继续展示上次已完成结果。同一连续方向机会使用原 signal epoch 去重，不会因为触发次数增加或结果保留期结束就重复生成 Episode。

## 四类触发如何理解

| 家族 | 程序观察的轻量变化 |
|---|---|
| `ORDER_FLOW_CHANGE` | OFI 强度与相邻采样的 OFI 变化 |
| `AGGRESSIVE_TRADE_BURST` | 近一秒主动买卖金额失衡与成交名义金额突增 |
| `BOOK_IMBALANCE_DEPTH` | 前 20 档买卖深度失衡与深度下降 |
| `PRICE_VELOCITY` | 短时价格速度与速度变化 |

每个资产用自己的历史计算 robust-z。默认 z ≥ 3 为 ABNORMAL，z ≥ 6 为 EXTREME；任一 EXTREME 或同一默认 1 秒窗口内两个不同家族 ABNORMAL 才触发完整评估。单个 ABNORMAL 不够。公式与数据窗口见 [验收记录](ACCEPTANCE.md#实际指标与工程默认值)。

四类 Alpha 使用 Binance 主场所数据；OKX 继续参与完整特征、交易资格和数据保护。严重度表示相对历史的异常程度，不是上涨概率、买卖方向或收益保证。

相同触发在原上下文内合并；更强证据可以升级同一个 trigger ID。候选结束后，持续异常需先退出组合触发条件才能重新触发。因此 `trigger_count` 与原始触发事件记录条数可能不同。

## 配置修改流程

先在诊断面板点击“载入当前触发配置”，复制保存当前 JSON，再编辑并保存。所有参数的默认值和合法范围见 [触发配置](EXECUTION.md#v104-运行时触发配置)。当前保存值可能与源码默认值不同。

此处指全局触发配置：保存仅允许 OBSERVE、无持仓且没有待处理订单。成功后会推进 `trigger_config_version` 和全局 `config_version`、关闭原候选 / Episode、暂停正在运行的 Shadow，并重新积累当前版本样本。即使保存相同内容，当前实现也会推进版本；没有修改时无需再次保存。

参数单位为毫秒、无量纲 z 或比例小数。`depth_drop_fraction=0.5` 表示 50%；四个 `enabled_families` 布尔值的顺序固定为上表顺序。数据过期与断档保护不能关闭；界面没有“所有资产固定每秒完整扫描”的生产开关。

调整前后使用封存行情作离线比较，再决定是否保存；系统没有自动阈值调优。已保存的旧 JSON 可以重新人工保存，但这会创建另一个新配置版本，不会恢复旧样本资格或回滚历史。

## 看诊断与漏斗

| 字段或计数 | 含义 |
|---|---|
| `pulse` / `trigger_decision` | 最近轻量采样与组合判断；触发成立只授权完整评估 |
| `trigger_origin` | 当前运行上下文的来源；为空不代表没有历史触发 |
| Episode 的 `origin_trigger_id` | 正式预测建立时的来源；旧预测没有此字段时不补造 |
| `full_evaluations` | 当前标的运行计数；重启或保存触发配置会重置，与持久化漏斗累计范围不同 |
| `family:*` / `combination:*` | 按家族或家族组合分组；一条触发可计入多个家族，不能直接相加当总数 |
| `evicted_links` / `scope` | 内存报告保留范围与淘汰数；完整事件仍可从持久化审计查找 |

漏斗为 Trigger → Full Evaluation → Episode → QUALIFIED → AUTO ADMITTED → EXECUTED → Outcome / Trade。AUTO 准入只计 `context=LIVE` 的 ADMITTED；观察模式的 SHADOW 准入不计入。这里 LIVE 表示私有执行上下文，交易所模拟账户也使用该上下文；是否真实资金仍取决于执行环境。EXECUTED 需要确认非零成交，提交意图或 ACK 不算。

Episode 创建率分母为触发数，资格率为 Episode 数，准入率为已合格 Episode 数，执行率为 Episode 数。无 Episode 候选率的分子只含正常结束且未生成 Episode 的候选，分母仍为该组全部保留触发数；未结束、数据中断、重启、配置切换不计入分子。该指标并非“已结算触发中的失败率”。

`observed_net_ev` 来自可学习 Outcome 的价格路径减配置成本；PAPER 和 Live 净损益分别统计，不能把观察净优势当成实际成交收益。旧记录、被淘汰关联和未闭合样本的口径见 [分析说明](ACCEPTANCE.md#分析口径与使用入口)。

## 离线比较与报告阅读

先完成 [回放步骤](OPERATIONS.md#封存录制与回放)，报告重点看：

| 字段 | 读法 |
|---|---|
| `evaluation_reduction` | 相对固定步进的完整评估减少比例；可为负数，减少也不单独证明策略更好 |
| `useful_reference_episodes` | 有效闭合且曾合格，或开场预期净优势和实际观察净优势均为正的参考样本数 |
| `matched_useful_episodes` | 按标的、方向、配置与候选 TTL 时间容差一对一匹配的数量 |
| `potentially_missed_episodes` | 没有匹配到的参考机会明细，需要结合价格路径复查 |
| `ignored_control_records` / `limitations` | 被排除的控制记录数量与研究重算的限制 |

参考样本数大于 0 时，可计算 `漏机会数 / useful_reference_episodes`；分母为 0 时显示“证据不足”，不能解释为零漏机会。对照从会话起点的冻结模型 / 配置冷启动，只沿用风险和触发配置命令；不会重现私有执行账本，也不会自动推荐或保存新阈值。

v1.0.4 历史对照的合成夹具捕获了两次参考有效机会，评估减少 88.75%；有限真实录制减少 26.33%，但有效参考分母为 0。这些是特定录制的结果，原始对照见 [v1.0.4 历史验收](ACCEPTANCE.md)，当前回归与资金执行边界见 [v1.1 验收](ACCEPTANCE-v1.1.md)。

动态资产的四个 Alpha 触发族可分别校准相对 robust-z 阈值；风险和数据完整性仍立即保护持仓。币种详情的 Trigger Profile 是独立入口，更新该资产触发档案与预热状态，不推进全局配置版本；手动填写阈值不会自动标记分布已校准。

0.5.1 的首页、预测和雷达按各币种有效配置 / 版本判断当前机会的新鲜度。只修改 ETH 的研究参数，不应使 BTC 的机会因全局版本误变而消失；保存全局配置则仍会改变全部资产上下文。Model Trust 取当前运行态，历史开场等级继续使用冻结记录。

Pulse 的秒级预热和资产晋级默认 24 小时连续健康数据是不同要求。资产资格另外检查最近一小时重置 / 重连次数，超过 3 次为 `book_stability` 硬失败；不能把总重连计数直接当作这个滑动窗口值。扫描器与机会雷达的具体使用见 [v1.1 指南](UNIVERSE-GUIDE.md)。
