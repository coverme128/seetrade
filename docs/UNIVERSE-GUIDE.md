# v1.1 动态币种池：个人使用

程序版本 0.5.2，对齐 `micro-alpha-trading-v1.1-upgrade-for-codex-v1.0.4-base`。保留 v1.0.4 的事件触发、首次触达标签、交易资格、AUTO 准入和独立持仓保护。

## 日常流程

1. 打开“币种扫描器”，先点“立即扫描”。首次迁移默认关闭定时扫描，保留 BTC/ETH 采集；原行情记录、结果、模型和账户检查点不删除。
2. 看研究优先级、资格明细和未知项。HIGH 是值得优先研究，不是买入评级。公共扫描无需账号或 Key；Binance、OKX 任一来源失败会显示 PARTIAL，不把失败当成退市。
3. 输入 `SOLUSDT` 或 `SOL-USDT-SWAP` 点“验证并扫描”。只有在交易所元数据中确认的 USDT 永续合约才能进入采集。支持交易所实际提供的中文合约名称。
4. 点“开始采集”。默认共 12 个采集槽位，包含 BTC/ETH。也可取消“只扫描，手动决定采集”，让后续扫描在空闲槽位内采集 HIGH 候选。此操作不授予 PAPER、CONFIRM 或 AUTO。
5. 积累连续数据与自动 Outcome；币种详情显示预热和模型状态。默认需 24 小时连续健康数据，新上市七天内的资产资格要求加倍连续时间。断流、重启会重新累计连续性，既有历史保留。
6. 点“研究此币种”。训练按 symbol、source、配置版本和 H/T/S 隔离；输出候选模型、校准报告、币种成本/风险统计和 24 组 H/T/S 回放。数据不足会生成拒绝报告，不会自动晋升。
7. 在该币种档案下导入研究工件，运行影子比较。人工晋升需要离线、在线证据和原有操作门槛全部通过。修改币种参数会使已有校准失效，必须重新研究。
8. 数据预热完成后，“校准当前触发分布”用该币种历史脉冲逐点计算因果 robust-z 分布，输出四个触发族各自的阈值、分布摘要哈希和版本。它不会改变模型概率或开放交易权限。
9. 观察和模型校准通过后，点“检查晋级 ELIGIBLE”。默认还要求同模型、同配置累计 2,000 条有效 Outcome、至少三个时间上分开的扫描周期通过，以及 Model Trust 不为 LOW。无人工晋级，系统不会自动进入实盘。
10. 在“机会雷达”看已形成的正式 Episode。默认隐藏空闲币种、没有 Episode 的瞬时触发和已失效/受阻机会。绿色优先、蓝色合格、黄色待验证、红色受阻、灰色暂不可用；可按等级或时间排序。点卡片进入原有预测详情与交易检查。
11. 到“每日复盘”按币种查看正式机会与执行结果，再按模型 / 配置分组评估。扫描 HIGH 数量不计入正式机会，不用全池累计样本替代单币门槛；日常步骤见 [每日复盘指南](DAILY-REVIEW.md#每天如何复盘)。

新币的 PAPER 权限也需要在档案中显式授予；任何模拟入场仍须经过校准、交易资格和组合门禁，不能靠开启 PAPER 强行造交易。默认双交易所特征要求保持不变：单场所币种可以被发现和采集，但缺失交叉场所特征时不能通过完整交易资格。

## 配置位置与默认值

在币种详情的“版本化研究参数与组合设置”中编辑并验证 JSON。保存进入同一持久化审计链；值域不符会被拒绝。

| 范围 | 默认值 / 作用 |
|---|---|
| 定时扫描 | 关闭；启用后默认 300 秒，界面支持 60/300/900 秒，自定义范围 60–86400 秒 |
| 候选采集槽位 | 12；允许 2–24，不能低于现有采集数量 |
| 数据预热 | 24 小时；配置最低 1 小时，不能据此推断真实交易可靠性 |
| 晋级 Outcome | 2,000 条；实际长期计数独立于 2,000 条内存结果缓存，且按资产/模型/配置分组 |
| 软降级 | 连续三个有时间间隔的失败周期降为 DEGRADED，再持续三个周期暂停 |
| 硬拒绝 | 价差、深度、滑点、波动、跳变、簿稳定性或交易所不可用等硬失败立即拒绝/暂停；已持仓保留保护 |
| 组合实盘 | `live_enabled=false`；独立于全局 CONFIRM/AUTO 以及交易所环境授权 |
| 模拟组合门禁 | 默认执行；可设为仅影子检查，决策仍记录 |
| 组合上限 | 3 个仓位；总有效杠杆 1.0，同方向 0.75，单资产 0.5，交易所 1.0，高相关组 0.5 |
| 总风险预算 | 账户权益的 0.5%；单笔风险和已有执行名义上限仍同时约束 |
| 相关性 | 最近至多 120 个对齐收益对，至少 30 对；阈值 0.8。证据缺失时，同方向按相关处理 |

每个币种都有版本化模型、特征分布、触发、成本和风险配置。界面的 `UNKNOWN/未知` 表示未观测，不是零。扫描不扩展 OI、强平流、新闻或 AI 选币；相关可选字段保留空值。

### 按交易所区分成本

币种配置中的 `venue_costs` 可填写 `binance`、`okx`，每项包含 `fee_bps`、`slippage_bps`、`impact_bps`、`adverse_selection_bps`、`funding_bps` 五个非负数字，单位 bps。下例是 `venue_costs` 字段的值，不是完整币种配置；先载入当前完整配置，再修改其中该字段，避免遗漏字段被填回默认值：

```json
{"okx":{"fee_bps":5,"slippage_bps":2,"impact_bps":1,"adverse_selection_bps":1,"funding_bps":0.5}}
```

该例仅展示格式，费率和滑点应按个人账户及观测证据填写。配置了执行交易所后，成本计算使用对应场所的假设；未配置时按 Binance 主行情计算。没有覆盖项时沿用该币种的基础成本假设。OKX 资金费使用 OKX 新鲜数据，价差取双场所中较保守者。修改成本会使该币种回到 CALIBRATING 并撤回交易权限；不能用低估成本来跳过重新验证。

## 研究产物

输出到当前数据目录的 `research/<job_id>/`：

- `challenger.json`、`report.json`：原有三个时间窗口、purge 边界、独立测试集、市场状态分组校准；文件哈希与报告绑定。数据不足时没有可晋升模型。
- `asset-profile-research.json`：所选币种实际观测过的 H/T/S、成本组成和尾部风险描述。成本假设与交易所真实成交明确分开。
- `asset-grid.json`：从当前会话 JSONL 的固定字节边界回放 24 个参数候选。复用同一引擎的 Market Pulse、Episode 和 First Hit；跳过操作命令，始终 OBSERVE。未结束或失效 Episode 不变成训练标签。该文件是参数探索证据，选出的参数仍需重新做时序验证，不能按最高均值直接交易。

可单独运行：

```bash
source scripts/env.sh
.venv/bin/python research/train.py --db data/personal/live.sqlite --source live --symbol SOLUSDT --model score --output data/research-sol
# 使用一份真实存在的录制文件，勿把示例文件名当作当前路径
target/release/micro-alpha-engine --research-grid 'data/personal/live-<session>.jsonl' SOLUSDT data/research-sol/asset-grid.json
```

研究任务由同一个受控队列执行，最多同时一个。定时任务可在 `research_schedule` 中传 `symbol` 固定范围；不会自动改参数或晋升。长时间采集所需磁盘和 CPU 随采集币种数增长；12 个槽位是资源上限配置，不是已完成 12 币长期容量验收的声明。

## 实盘与回退

CONFIRM/AUTO 增仓必须依次通过原交易资格、AUTO 准入（仅 AUTO）、资产权限和组合门禁。组合门禁只能维持、减少或阻止个别计划，不能放大仓位；执行意图引用持久化的组合决策。发送前按最新账户和待成交订单重新检查。减仓/退出不受新风险权限关闭阻挡。

“冻结动态池并切回观察”会关闭扫描计划、停止新的动态采集与入场，活动工作集回到 BTC/ETH；其他币种已有仓位或待处理订单继续保留行情和保护。档案、迁移表、录制文件与状态变迁不删除。“解除动态池冻结”不会自行开启定时扫描或实盘。

回退优先使用该按钮。若要回退旧程序二进制，必须先处理所有新增币种的仓位/待处理订单，再按备份恢复流程操作；旧版没有动态保护线程和细价格精度，不能直接接管这些持仓。

## 本地接口与隔离验收

沿用 `GET /api/state`、`GET /api/history`、`POST /api/control/<command>`。新增控制：`scanner_config`、`scanner_run`、`asset_add`、`asset_collect`、`asset_config`、`asset_trigger_config`、`asset_trigger_calibrate`、`asset_review`、`asset_permissions`、`asset_model_rollback`、`portfolio_config`、`universe_rollback`。`shadow_start`、`research_run`、`research_schedule` 支持 `symbol`。`scanner_started/scanner_result` 只能由本机内部 worker 写入，浏览器不能伪造扫描结果。

默认端口不变。仅为并行隔离验收增加三个可选环境变量：`MICRO_ALPHA_PORT`（核心，默认 8787）、`MICRO_ALPHA_CORE_URL`（网页代理目标，默认 `http://127.0.0.1:8787`）、`MICRO_ALPHA_WEB_ORIGIN`（额外允许的本地网页 Origin）。生产使用默认值即可。

## 0.5.1 配置与证据一致性修复

- 币种级滑点、时效、加减仓参数及反馈阈值沿用同一资产配置；账户累计亏损、回撤和 AUTO 总预算仍是账户级限制。AUTO 同时遵守账户与币种的严格门槛。
- `venue_costs` 会解析成同一份有效成本配置，贯穿预测冻结、研究工件、影子导入、PAPER 成交和反馈统计。模拟持仓保存入场时的成本配置及执行场所；新增币种配置不会改写已持仓的参数。
- 每个资产可有独立 config_version。修改 ETH 不推进 BTC 的当前版本；修改账户级全局配置则让所有币种进入新的上下文。历史记录保留，研究默认筛选当前有效版本。
- 共享模型晋升/回退会追加 BTC/ETH 档案版本、更新校准引用。已经独立配置的资产不被共享模型覆盖；需要分别运行币种影子验证。
- 生命周期记录附带规则版本、有效配置版本、当时扫描规则与固定策略标识。Model Trust 直接显示运行态可信度，避免重复维护一份可能过期的档案值。
- 固定策略 `asset-quality-v1.1.1-reset3h-slip100-500-1000`：最近一小时超过 3 次序列重置/断线重连判为 book_stability 硬失败；滑点探针保留 100/500/1000 USDT。沿用固定的硬失败分类；这些规则有版本与记录，个人版不增加任意规则编辑器。
- 组合面板的“占用币种（含待成交）”按币种去重，避免同币种仓位与挂单重复计数。

## 升级到 0.5.1 后的检查

1. 按 [运维手册](OPERATIONS.md#停机备份与恢复) 保存数据和代码，使用原 `MICRO_ALPHA_DATA` 启动。此修复无需新增 Key、环境变量、数据库服务或 GPU。
2. 确认页面版本 0.5.1、模式 OBSERVE，检查已采集币种行情、存储与模型状态。旧检查点缺少独立版本字段时沿用原全局版本，首次修改币种配置才分配独立版本；不必为了升级逐个重存未改动的配置。
3. **升级前已经设置过 `venue_costs` 的币种需要重新保存完整配置。** 这会生成该币种新版本、回到 CALIBRATING 并撤回交易权限；使用修复后产生的新版本样本重新研究、影子验证和人工晋升。历史中错误冻结的成本不会被重写，旧成本口径工件不能用于新配置晋升。
4. 修改单币参数后，在 `/api/state` 的 `symbols[symbol].config_version` 核对有效版本；不要只看顶层全局版本。只修改 ETH 不应使 BTC 换版本。保存全局配置或全局触发配置会更新全部资产上下文，独立配置值本身仍保留。
5. 在币种详情核对当前 Model Trust、流动性引用、状态变迁的规则 / 配置版本；组合摘要的“占用币种（含待成交）”按币种去重。继续按原门槛积累证据后再开放 PAPER 权限。
