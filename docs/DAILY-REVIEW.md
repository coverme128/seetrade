# 每日复盘与效果评估

适用版本：个人版 0.5.2 / 合同 v1.1。该模块复用原有预测、Outcome、准入、订单和交易记录，只读取证据、生成统计，不改变模型、标签、配置或交易权限。

## 日常使用

打开左侧“每日复盘”。默认按北京时间查看今天，可选择历史日期或“累计评估”，输入 `BTCUSDT` 等规范化币种筛选。数据来源跟随当前工作区，明确区分真实行情与合成行情。页面按需读取；需要最新证据时点击“刷新复盘”。

先看正式机会、曾通过资格、有效 / 失效 / 待完成数量，再看执行去向与已平仓效果。展开机会流水可查看开场等级、模型 / 配置版本、拒绝原因、订单状态、平仓结果和独立到期观察。扫描器 HIGH 仅是研究优先级，没有生成正式预测的候选不计为机会。

分页每页 50 条；汇总始终来自完整 SQLite 历史，不受原历史接口 500 条上限影响。翻页与“导出完整 JSON”锁定同一记录编号及截止时间，导出包含全部匹配机会、平仓流水、版本分组和诊断。刷新会取得新的证据快照。

## 每天如何复盘

1. **确认范围。** 查看日期、数据来源、币种和报告截止时间。今天的报告仍在变化；第二天查看昨日，跨日机会的最终结果看累计评估。
2. **先看证据是否够用。** 核对正式机会、有效 / 失效 / 待完成数量及版本分组。重点检查失效原因，不能只看留下来的有效样本。
3. **核对机会去了哪里。** 展开流水，区分仅观察、资格受阻、准入拒绝、人工跳过、待确认、已成交和已平仓。没有成交时先查具体原因，不能据此评价执行收益。
4. **分别看预测和成交。** 预测看有效结果、校准误差与观察净优势；成交看对应执行环境的已平仓净损益、成本偏差及回撤。按币种、模型和配置版本比较，不混用 PAPER 与真实资金结果。
5. **留下可复查的结论。** 导出完整 JSON，记录主要问题和下一步：继续积累、检查断流、核对成本，或进入研究流程。参数修改后使用新版本样本验证。

个人使用的最低准备是：已安装运行依赖、固定且可写的 `MICRO_ALPHA_DATA`、核心持续运行。复盘本身不需要交易所账号、API Key、Python、GPU 或新增服务；真实行情采集仍需公共行情网络。离线读取已有数据库不需要联网。

## 统计口径

| 指标 | 口径 |
|---|---|
| 正式机会 | 按来源和 prediction ID 去重，以预测开场时间归属日期 |
| 曾通过资格 | 截止报告时间已有明确 QUALIFIED 证据；开场颜色仍只使用开场快照 |
| 预测结果 | 目标、止损、超时、信号失效、数据失效分别统计；未结束为待完成 |
| 有效样本 | 只读取原 `learning_eligible` 标记，不根据后续涨跌重新改标签 |
| 目标触达率 | 有效结果中 TARGET_HIT 的比例，不是成交胜率；无有效样本显示未知 |
| 校准误差 | 有效且保存开场校准概率的样本，按 10 个概率桶计算目标触达 ECE；JSON 另含二元目标触达 Brier，不混入原始未校准概率 |
| 观察净优势 | 有效 Outcome 的价格路径收益减假设成本，不是模拟或真实成交损益 |
| 执行去向 | 已平仓、已有成交未平仓、待确认订单、未成交、人工跳过、仅观察、准入 / 执行受阻等；没有证据时不猜测“人工未确认” |
| 影子准入 | 仅为预演，单独展示，不能当作交易所真实执行决定 |
| 订单统计 | 期间创建或更新的订单，按 client ID 保留截止时最新状态；ACK / NEW 不等于成交 |
| 已平仓净损益 | 按平仓日期统计，包含前日开场仓位；PAPER、交易所模拟、真实资金及未知环境分别汇总，不合并收益 |
| 资金费修订 | 同一交易更新已知结果，不重复计为新交易；截止时间之后的修订不进入历史日报 |
| 成本偏差 | 已平仓交易的实际成本减预计成本，单位 USDT，只统计两者都有证据的记录 |
| 回撤 | 平仓顺序的累计已平仓净损益峰谷差，单位 USDT；不含浮动盈亏，不代表账户最大回撤 |
| 加仓与分批退出 | 汇总到原始入场交易，不为每条加仓信号重复分配整笔损益 |
| 版本对比 | 预测按来源、币种、模型及配置版本分组；成交另按执行环境和场所分组。不同时间或市场状态下的表现不能直接证明升级改善 |

没有成交时，不填造零收益、零回撤或零成本。旧记录缺少执行环境、版本或退出原因时保留 UNKNOWN。原始 JSON 无法解析时提示报告不完整。

## 跨日与累计

历史日报只使用该北京时间自然日结束前已落盘且当时已知的证据。23:59 开场、次日结束的预测，在开场日报中仍是待完成；次日平仓进入次日成交汇总。查看累计评估可关联其最终结果。

例如预测后来上涨，但未发生入场，结果是观察预测的市场表现，不会新增盈利交易。信号提前关闭后的 `outcome_horizon` 是独立到期观察，既不改写原结果，也不恢复其训练资格。当前有效样本可能是被筛选后的子集，应同时检查失效分布。

## 自动日报与文件

核心启动后以及运行期间每 5 分钟检查一次，自动保存上一北京时间自然日的完整 JSON：

```text
<MICRO_ALPHA_DATA>/reviews/<live|demo>/review-YYYY-MM-DD.json
```

先写临时文件再原子替换；已存在的归档不重复覆盖。失败会记录核心日志并重试，不阻断交易引擎。任务在核心锁外执行，只读数据库，不发送网络消息，不需要账号或额外服务。

重启补上一日；长期停机期间的更早日期在页面选择并导出，不自动批量补齐。今天的报告仍在变化，通过页面查看或导出。核心停止时不会生成日报；这不是操作系统后台守护服务。归档保存的是生成时的固定证据，之后的账务修订在新的累计报告中查看。

## 如何用于迭代

诊断会提示样本不足、失效过多、观察净优势为负、没有已平仓验证或记录异常，并给出下一步核查方向。它不是模型验证通过结论：即使样本超过提示阈值或单日盈利，仍需现有研究、时序隔离、Shadow 和 PAPER 门槛。

优先排查数据连续性和标签 / 生命周期，再比较成本、预测期限与退出行为。程序错误用回归测试验证；策略修改保留版本，用独立样本和影子比较验证，不根据一天的损益自动改参数或晋升。

| 诊断代码 | 含义与下一步 |
|---|---|
| `NO_OPPORTUNITIES` | 范围内没有正式预测；先核对来源、日期、采集与触发状态 |
| `INSUFFICIENT_SAMPLES` | 有效样本少于 100；继续按版本积累，100 仅为提示阈值，不是晋升或交易门槛 |
| `HIGH_ATTRITION` | 失效数量多于有效数量；检查信号变化、数据中断及筛选偏差 |
| `NEGATIVE_OBSERVED_EDGE` | 平均观察净优势为负；核对成本、期限和屏障，不直接解释为账户亏损 |
| `NO_CALIBRATED_EVIDENCE` | 有有效结果却没有开场校准概率；进入研究流程，不把原始概率当成验证结果 |
| `NO_CLOSED_TRADES` | 无已平仓成交；检查执行流水，尚不能评价成交收益 |
| `MULTIPLE_COHORTS` | 涉及多个币种或版本；分别看分组，不用总样本替代当前版本证据 |
| `MISSING_TRADE_EVIDENCE` / `INCOMPLETE_RECORDS` | 缺少执行环境 / 损益或历史记录无法解析；先检查原始证据，保留未知值 |
| `RESEARCH_REQUIRED` | 提醒所有复盘结论仍需独立研究、Shadow 和 PAPER 验证 |

后续请把完整报告与简短问题描述一起交给开发者分析：保留日期 / 时区、来源、币种、模型 / 配置版本、`as_of`、`through_id`，并标出代表性的预测或交易 ID。这些信息可区分策略问题、执行问题与软件问题。不要附带 `.env.local` 或 API 凭证。

程序会自动生成归档和规则诊断；深入分析、代码修改和升级验证需要另行开展。没有自动提交修复、调整策略或晋升模型的后台代理，也没有邮件或消息推送。

## 接口与离线导出

`GET /api/review` 支持：

| 参数 | 含义 |
|---|---|
| `date` | `YYYY-MM-DD` 或 `all`；默认今天，拒绝无效与未来日期 |
| `source` | 可选 `live` / `demo`；不传时仍按来源分组 |
| `symbol` | 可选规范化币种，如 `BTCUSDT` |
| `offset` / `limit` | 明细分页，默认 0 / 50，单页最多 200；不截断汇总 |
| `through_id` / `as_of` | 使用上次响应的编号和时间保持分页 / 导出一致 |
| `export=true` | 返回全部匹配机会明细，不应用分页截断 |

`source=live` 表示真实公共行情，可能对应仅观察、PAPER、交易所模拟或真实资金执行；它不是实盘开关。网页跟随当前工作区来源。接口只查询当前实例的数据存储，不跨数据目录合并历史。

服务运行时，可从核心只读查询或导出；把日期和币种换成实际范围：

```bash
curl --fail --silent --show-error 'http://127.0.0.1:8787/api/review?date=all&source=live&symbol=BTCUSDT&limit=50'
mkdir -p data/review-exports
curl --fail --silent --show-error 'http://127.0.0.1:8787/api/review?date=2026-10-07&source=live&export=true' -o data/review-exports/review-2026-10-07.json
```

上述两次独立请求各自获取新快照。要复现同一次分页或导出，保留原筛选条件，并传回响应中的 `through_id` 与 `as_of`；网页自动处理。`as_of` 是 Unix 毫秒时间，报告自然日始终按 `Asia/Shanghai` 划分。

| JSON 字段 | 用途 |
|---|---|
| `schema`、`date`、`timezone`、`as_of`、`through_id` | 格式版本、统计范围与证据快照 |
| `source_filter`、`symbol_filter`、`provisional` | 筛选条件，以及日期窗口是否尚未结束；不表示策略是否通过验证 |
| `summary`、`cohorts` | 全范围机会汇总，以及来源 / 币种 / 模型 / 配置分组 |
| `execution`、`trading`、`trade_cohorts` | 执行统计、按环境及场所汇总的成交效果、进一步按币种和版本分组 |
| `rows`、`pagination` | 机会流水及分页信息；`export=true` 导出全部匹配机会 |
| `closed_trades` | 按平仓日纳入的成交账本，与开场日机会数量不必一致 |
| `diagnostics`、`malformed_records`、`limitations` | 问题提示、无法解析的记录数及统计边界 |

核心未启动时也可只读数据库导出：

```bash
source scripts/env.sh
mkdir -p data/review-exports
cargo run --locked --example review_report -- data/live-validation/live.sqlite 2026-10-07 data/review-exports/review-2026-10-07.json
cargo run --locked --example review_report -- data/live-validation/live.sqlite all data/review-exports/review-all.json
```

将目录及日期替换为实际值。接口和命令使用同一汇总代码；数据库无需新增表或迁移，原录制及黄金回放保持兼容。
